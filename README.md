# elaction

Ремейк аркадной игры **Elevator Action** (Taito, 1983) на Godot 4.

Механика — как в оригинале: агент Otto спускается с крыши тридцатиэтажного здания,
собирает документы за красными дверями, ездит на лифтах, отстреливается от вражеских
агентов и уходит на машине. Картинка — современная: динамический свет, нормал-мапы,
пост-обработка. Лампы на этаже можно прострелить, и этаж погрузится в темноту.

| | |
|---|---|
| Движок | Godot 4.7.2 |
| Язык | GDScript со статической типизацией |
| Платформы | Windows, Linux |
| Статус | M7a — ассеты окружения: коробки заменяются текстурами со светом |

## Что уже работает

Окружение собрано из ассетов: перекрытия, стены, окна, двери, кабина, эскалатор,
лампа и выход нарисованы генератором и приходят с нормалью и бликом, поэтому свет из
M6 ложится на рельеф. Цветными прямоугольниками остались только Otto, агенты и пули —
их черёд в M7b.

- Otto ходит, приседает и прыгает; из приседа не встаёт там, где не хватает места.
- Лифт: кабина слушается изнутри, пустая ездит сама, на крыше катаются без управления.
  В открытый проём шахты можно упасть насмерть, под опускающейся кабиной — погибнуть.
- Эскалаторы: посадка с площадки нажатием, во время поездки Otto неуязвим.
- Двери: за красными документы по 500 очков, внутри двери можно пересидеть до пяти
  секунд. Выход из здания без всех документов возвращает к верхней несобранной двери.
- Бой: пистолет с ограничением в три пули на экране, удар ногой в прыжке, враги-агенты
  выходят из дверей и стреляют. Три жизни, respawn и Game Over.
- Лампы: сбитая падает, убивает агента под собой и гасит этаж; в темноте агенты видят
  хуже, а убийства стоят на 50 очков дороже.
- Здание на 30 этажей собирается генерацией по сиду: шахты не сквозные, на стыках —
  эскалаторы, пять документов разнесены по высоте.
- Игровой цикл: собрал документы, вышел — бонус и следующее здание, где агенты злее.
  Провозился — сирена, и до конца здания её не снять.
- Свет: этаж светел, пока на нём горит лампа. Сбили — этаж падает до общего тона
  здания и остаётся таким навсегда. Светятся шахты лифтов и выстрелы, за окнами
  стоит город, выложенный из того же сида, что и само здание.

## Запуск

### Что нужно поставить

- [Godot 4.7.2](https://godotengine.org/download) — на Windows проще через winget:

  ```powershell
  winget install --id GodotEngine.GodotEngine
  ```

- Python 3.12 или новее — для линтеров, хуков и генератора ассетов.

Только для перерисовки ассетов — играть и проходить проверки можно без него, потому что
готовые PNG лежат в репозитории ([ADR-0011](docs/adr/0011-asset-pipeline.md)):

- [Blender 5.2.1](https://www.blender.org/download/) — рендер актёров:

  ```powershell
  winget install --id BlenderFoundation.Blender
  ```

### Настройка окружения

```powershell
python -m venv .venv
.venv/Scripts/pip install -r requirements-dev.txt
.venv/Scripts/pre-commit install
.venv/Scripts/pre-commit install --hook-type pre-push
```

### Запустить игру

```powershell
godot --path .
```

### Открыть в редакторе

```powershell
godot -e --path .
```

## Управление

| Действие | Клавиатура | Геймпад |
|---|---|---|
| Движение | Стрелки или WASD | Крестовина, левый стик |
| Присед | Вниз или S | Крестовина вниз |
| Прыжок | Пробел или Z | A |
| Выстрел | X или J | X |
| Пауза | Esc | Start |
| Снимок экрана | F12 | — |

На паузе: **Esc** — продолжить, **R** — начать заново, **Q** — выйти.

«Вверх» и «вниз» работают по месту: в кабине лифта они ведут её, на площадке эскалатора
отправляют в поездку, на коврике у двери — внутрь. На этаже «вниз» — обычный присед.

## Проверки

Хуки прогоняются сами: `gdformat` и `gdlint` на коммите, импорт проекта движком и тесты —
на push. Полный прогон вручную:

```powershell
tools/check.ps1
```

Тот же набор проверок выполняет CI на каждый push и pull request.

Отдельно:

```powershell
python tools/run_tests.py     # тесты GUT
python tools/godot_check.py   # импорт и разбор скриптов
python tools/capture.py M7a   # скриншоты вехи в screens/M7a/
```

Ассеты лежат в репозитории готовыми, но рисуются кодом — при правке палитры или
геометрии их перерисовывают:

```powershell
python tools/render_env.py         # окружение: диффуз, нормаль, блик
python tools/blender_bin.py        # проверить, что Blender найден
```

Свет проверяется не сценарием съёмки, а отдельным инструментом: он ждёт состояние,
а не выдержку, и потому снимает именно то, что обещает.

```powershell
godot --path . res://tools/light_shot.tscn            # кадры света на живом здании
godot --path . res://tools/light_shot.tscn -- --folder=M7a --seed=3
godot --path . res://tools/light_shot.tscn -- --bench # сколько стоит кадр
godot --path . --script res://tools/light_bench.gd    # потолок источников света
```

Здание собирается из сида, поэтому проверяется на трёх уровнях сразу: правила без сцены,
свойства раскладки на десятках сидов и собранное здание, которое проходит бот. Зачем так
и почему бот водится по состоянию, а не по секундомеру — в [`docs/testing.md`](docs/testing.md).
