## 1. Цель

Выпустить на PC законченную аркадную игру, которая:

1. воспроизводит механику Elevator Action (Taito, 1983) **без изменений в геймплее**;
2. выглядит современно — за счёт динамического 2D-освещения, нормал-мап и пост-обработки,
   а не за счёт переизобретения дизайна;
3. на каждом коммите проходит автоматические проверки.

Формула проекта: **механика 1983 года, картинка 2026 года.**

## 2. Definition of Done эпика

- [ ] Полный игровой цикл: вход с крыши → сбор всех документов → выход к машине → следующее здание
- [ ] 30 этажей, лифты, эскалаторы, двери, враги-агенты, стрельба, удар ногой
- [ ] Отстреливаемые лампы и затемнение этажа
- [ ] Жизни, счёт, таблица рекордов, экран Game Over
- [ ] Главное меню, настройки, поддержка геймпада
- [ ] Сборки под Windows и Linux собираются в CI по тегу
- [ ] Зелёный CI; игровая логика покрыта тестами (рендер — нет)

## 3. Границы

**Не входит в эпик:** мультиплеер, мобильные платформы, консоли, редактор уровней для
игроков, онлайн-таблица рекордов, 3D-геймплей, сюжетные вставки.

Онлайн-лидерборд вынесен в опциональный M10 — он единственный, ради чего в проекте
может появиться бэкенд и docker compose (см. [ADR-0003](adr/0003-no-docker.md)).

## 4. Механика оригинала — источник правды

Реализуем как в аркадном оригинале. Спорные детали сверяем с запуском ПЗУ в MAME,
а не по памяти.

| Механика | Суть | Веха |
|---|---|---|
| Otto | Агент 17. Ходит, приседает, прыгает, стреляет, бьёт ногой | M1 |
| Здание | 30 этажей, спуск сверху вниз, выход на первом этаже | M5 |
| Лифты | Кабина в шахте; управляется игроком; можно ехать на крыше; давит врагов | M2 |
| Эскалаторы | Автоматически перемещают между этажами | M2 |
| Двери | Обычные — из них выходят враги; красные — в них документы | M3 |
| Документы | 500 очков за штуку; собрать все до выхода из здания | M3 |
| Враги | Агенты стреляют, преследуют, появляются из дверей | M4 |
| Свет | Лампы отстреливаются, этаж темнеет | M4 + M6 |
| Финал уровня | Выход на первом этаже к машине | M5 |

**Требует сверки с оригиналом:** точное число красных дверей на здание, таблица очков за
врагов, правила респавна, поведение врагов в темноте, бонус на выходе.

## 5. Дорожная карта

Каждая веха — отдельная ветка и PR. Веха закрыта, когда выполнен её DoD и CI зелёный.

### M0 · Фундамент

Репозиторий, движок, тулинг, процесс.

- [x] Git-репозиторий, публичный, SSH
- [x] Godot 4.7.2, `project.godot`, базовые настройки рендера и карта управления
- [x] Структура папок и соглашения (`docs/conventions.md`)
- [x] `gdformat` + `gdlint` + pre-commit (на коммит) и проверка движком (на push)
- [x] CI на GitHub Actions: линт + импорт проекта
- [x] Минимальная запускаемая сцена `src/main.tscn`
- [ ] Тест-фреймворк GUT, первый тест, запуск в CI
- [ ] Закрыть [ADR-0002](adr/0002-visual-target.md): визуальный ориентир

**DoD:** `tools/check.ps1` проходит локально, CI зелёный, проект запускается.

### M1 · Otto ходит — вертикальный срез

Первое, во что можно играть. Графика — серые коробки, и это нормально.

- [ ] `CharacterBody2D` и машина состояний: idle / run / crouch / jump / fall / dead
- [ ] Гравитация, коллизии, пол этажа, ограничение по краям экрана
- [ ] Камера: следование за игроком, привязка к границам здания
- [ ] Grey-box тайлсет одного этажа
- [ ] Ввод: клавиатура (готово) плюс геймпад
- [ ] Тесты: переходы состояний, физика прыжка

**DoD:** Otto бегает, приседает и прыгает по одному этажу; тесты зелёные.

### M2 · Лифты и эскалаторы — ядро игры

Самая рискованная веха: тут вся физика взаимодействия с движущимися платформами.

- [ ] Шахта лифта как ресурс уровня (границы, этажи-остановки)
- [ ] Кабина: `AnimatableBody2D`, движение вверх и вниз, остановка на этажах
- [ ] Вход в кабину и управление ею, выход на этаж
- [ ] Езда на крыше кабины (перенос игрока платформой)
- [ ] Смертельное сдавливание игрока и врага кабиной
- [ ] Эскалаторы: автоматический перенос между этажами
- [ ] Тесты: перенос платформой, посадка и высадка, сдавливание

**DoD:** можно спуститься с верхнего этажа на нижний, используя лифт и эскалатор.

### M3 · Двери и документы

- [ ] Дверь как сцена: закрыта / открывается / открыта, коллизия входа
- [ ] Красные двери: вход Otto, получение документа, +500 очков
- [ ] Счётчик собранных документов в HUD
- [ ] Блокировка финального выхода, пока документы не собраны
- [ ] Тесты: сбор документа, условие разблокировки выхода

**DoD:** на тестовом здании из трёх этажей можно собрать все документы и открыть выход.

### M4 · Бой, враги, свет как механика

- [ ] Стрельба Otto: стоя, приседая, в прыжке
- [ ] Удар ногой в прыжке
- [ ] Враг-агент: выход из двери, преследование, стрельба, укрытие
- [ ] Пули как отдельные сущности, попадания, смерть
- [ ] Жизни, смерть игрока, респавн, Game Over
- [ ] Отстреливаемые лампы: этаж темнеет, враги ведут себя иначе
- [ ] Тесты: попадания, урон, счётчик жизней

**DoD:** этаж с врагами проходится с боем, лампы гасятся.

### M5 · Здание и игровой цикл

- [ ] Описание этажа и здания данными (`Resource`), а не хардкодом
- [ ] Сборка 30 этажей, вертикальный стриминг — активны только видимые этажи
- [ ] Выход на первый этаж → машина → следующее здание
- [ ] Счёт, бонусы, нарастающая сложность
- [ ] Пауза, рестарт, переход между зданиями
- [ ] Тесты: генерация здания, условия перехода

**DoD:** игра проходится от первого здания до второго без вылетов, 60 FPS.

### M6 · Свет и атмосфера — графический слой

Ради этой вехи и выбран Godot. До неё игра выглядит как серые коробки.

- [ ] `CanvasModulate` (ambient) плюс `PointLight2D` и `LightOccluder2D` на этажах
- [ ] Нормал-мапы и specular на спрайтах через `CanvasTexture`
- [ ] Конусы света ламп, свет из шахты лифта, вспышки выстрелов
- [ ] Пост-обработка: bloom, виньетка, цветокоррекция
- [ ] Бюджет освещения: не более ~12 активных источников в кадре, профилирование
- [ ] Параллакс-фон города за окнами

**DoD:** тёмный этаж с тремя лампами и перестрелкой держит 60 FPS на целевом железе.

| Русский и английский интерфейс | M8 |

## 7. Процесс работы

- **Ветки:** `feat/m2-elevators`, `fix/elevator-crush`, `chore/ci-cache`. В `main` напрямую не пушим.
- **Коммиты:** Conventional Commits — `feat:`, `fix:`, `refactor:`, `test:`, `docs:`, `chore:`.
- **Перед коммитом:** хуки прогоняются сами. Вручную — `tools/check.ps1`.
- **Перед push:** дополнительно прогоняется проверка движком.
- **PR:** один PR на веху или на крупную задачу внутри вехи, merge только при зелёном CI.
- **Решения:** всё, что влияет на архитектуру, оформляется как ADR в `docs/adr/`.
